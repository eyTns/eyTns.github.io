# UI 취향 명세

수정 지시가 나올 때마다 항목으로 추가한다. 각 항목은 "지시 → 왜/어떻게" 구조.
이 게임을 모르는 에이전트도 읽을 수 있도록, 게임 고유 명칭에는 짧은 맥락을 붙인다.

## Mouse Maze

맥락: 격자 미로를 편집하고 결정론적 쥐가 걷는 것을 관람하는 게임. Maze 1은 벽이
타일 하나를 통째로 차지하고, Maze 2는 벽이 타일 사이 경계선 위에 놓인다.
사용자는 두 게임을 "1탄/2탄"으로 부른다 (대화용 호칭이며 UI에는 쓰지 않는다).

### 타이포그래피, 색

- 전부 대문자 표기 금지. 원작이 대문자였어도 따라하지 않는다. ("제일 무서운 건 모든 것이 대문자라는 점")
- 타이틀은 "Mouse Maze" 한 줄. 크기는 크게 유지하되 두 줄로 꺾지 않는다.
- 타이틀 밑의 태그라인("Build the maze. ...") 삭제. 멋 부린 부제를 붙이지 않는다.
- 게임 선택지 제목 색은 빨강 금지. 빨강은 버튼 텍스트에 이미 쓰여서 과함. 황금색(#f5c542)으로 정착.
- 히트맵(칸별 방문 횟수 시각화)에 빨강 계열 금지. 방문 10회에 빨개지니 "무섭다"는 반응.
- 히트맵 색 진행은 초록 → 연두 → 노랑 → 중간색 → 연보라 → 검정. 앵커는 방문 1/10/100/1000/5000회, 로그 스케일.
- 원본 스크린샷이 있으면 색은 눈대중이 아니라 픽셀에서 추출한다. 눈대중 벽돌색이 두 번 틀렸고, 벽돌 줄무늬가 면보다 밝다는 사실도 픽셀 분석으로야 발견됨.

### 레이아웃

- 버튼, 상태줄, 카운터 등 모든 컨트롤은 높이 고정. 내용이 길어지면 글자 크기가 줄어들지 칸이 커지지 않는다.
- 기능 버튼들의 위치는 어떤 상태 변화에도 움직이지 않는다.
- 잠긴(미해금) 버튼은 흐리게가 아니라 안 보이게. 단 DOM에서 제거하지 말고 visibility:hidden으로 자리를 지켜서, 해금 시 다른 버튼이 밀리지 않게 한다.
- 버튼 격자의 정렬 산수는 정확히 맞춘다. "속도버튼 3개 = 긴 버튼 1개 너비" 지시는 간격까지 계산해 오차 0으로 구현하고 검증했다.
- 업적 격자에서 남는 칸에는 빈 네모를 그리지 않는다. 12개를 5열에 넣어 마지막 줄이 자연히 비게 배치. (지시: 첫줄 moves 5개, 둘째줄 same tile 5개, 셋째줄 나머지 2개, 세 칸은 네모 없음)

### 문구, 표기

- 한국어 개념어와 영어 UI를 섞지 않는다. UI에 "both 탄"이라 썼다가 "개노답" 반응. UI는 "Maze 1", "both games"로, 대화에서는 사용자 호칭(탄)을 따른다.
- em dash, en dash 금지. 하이픈은 허용. 문서와 대화 모두.
- "박다" 표현 금지.
- 버튼 라벨은 실제 동작과 일치해야 한다. "Share maze" → "Share game": 공유되는 게 미로가 아니라 게임 페이지 링크였기 때문.
- 버튼 순서도 지시 대상이다. Save가 Load보다 앞 (swap 지시 있었음).

### 정보 노출

- 내부 수치를 화면에 쓰지 않는다. "mouse speed 2.5/sec 지우시오. 표시하지 마시오."
- 속도 조절 버튼에는 라벨, 설명, hover 툴팁이 전혀 없다. 셰브런 개수만이 신호. 지시 원문: "속도버튼이라는 설명은 없고, hover 해도 별다른 설명이 나오지 않고."
- 잠긴 기능은 상태를 누설하지 않는다. 턴 카운터가 잠겨 있으면 미로가 막혀 있어도 문구가 "길없음" 등으로 바뀌지 않고 잠김 문구 그대로여야 한다.
- 다른 플레이어의 미로(풀이)는 어떤 API 응답에도 포함시키지 않는다. 기록은 공개, 풀이는 비공개.

### 시스템은 사용자 선택을 대신하지 않는다

- 속도 해금이 그 속도를 자동 선택하면 안 된다. 해금은 버튼을 보이게만 하고, 선택은 사용자가 누를 때만 바뀐다. ("속도버튼을 게임 시스템이 누르지 마라")
- 저장 데이터가 손상돼 선택값을 복원할 수 없을 때의 기본값은 '가장 느린 해금 칸'이 아니라 '기본 속도 칸'. 나쁜 데이터 때문에 사용자를 느림에 앉히는 건 최악의 추측.
- "끝까지 건너뛰기" 류의 스킵 버튼 금지 ("하남자식 건너뛰기는 쓰고싶지 않음"). 관람이 길다는 문제는 속도 상한을 올려서 정면으로 푼다. 최종 속도 사다리는 사용자가 직접 수치 지정 (2/4/7.5/20/60/200 칸/초).
- 편집기가 사용자 배치를 몰래 고치지 않는다. 출구 마커를 벽 있는 칸으로 옮기면 벽을 자동으로 치우는 게 아니라 그냥 막힌 상태로 둔다. 이에 따라 "The exit tile has to stay open" 같은 보호 문구도 존재할 이유가 없다.
- invalid 상태에서도 실행 버튼은 누를 수 있다. valid면 "출발", invalid면 "출발 ⚠️" (여전히 클릭 가능), 누르면 통과 못함 문구 출력. 비활성화로 시도 자체를 막지 않는다.

### 그리기

- 반복 무늬(벽돌 등)는 타일 경계에서 빈 곳 없이 채운다. 지그재그 쌓기의 어긋난 줄은 클리핑으로 양끝 반 칸을 채운다. ("벽돌 모양의 왼쪽부분이 비어있는것 불편하다")
- Maze 2의 벽(타일 사이 경계선에 놓이는 막대)은 육각형: 긴 직사각형 양끝에 직각이등변삼각형이 붙은 형태. 원본 게임의 모양 재현 지시.
- Maze 2의 벽에도 Maze 1 벽돌 같은 줄무늬를 넣는다. 색은 Maze 1 벽과 동일하게.
- Maze 2에서 벽 없는 타일 사이 틈은 검정이 아니라 짙은 초록. 원본(rgb 0,68,0)보다 약간 연하게 시작했는데 "약간만 더 밝게" 추가 지시가 와서 rgb(0,98,0)에 정착. 이런 미세 조정은 반복될 수 있다고 전제.
- 입구에서 도달 불가능한 칸은 별도 벽돌로 채워 표시한다 (원본 Maze 2에 있던 표현을 두 게임 모두에 적용). 사용자가 세운 벽과 색이 달라야 하고 무늬는 같아도 된다. 색은 황토색, 두 게임 동일.
- 쥐(플레이어 말)는 순간이동하지 않고 칸 사이를 보간해 걷는다.
- 걷기는 여정의 양끝까지: 입구 밖 → 첫 칸 진입, 마지막 칸 → 출구 밖 퇴장도 중간 이동과 같은 보간. 마지막 걸음이 끝난 뒤에 결과 문구를 띄운다.

### 진행, 해금, 기록

- 느림 속도 버튼(속도 6칸 중 1번 슬롯)은 첫 탈출 업적으로 해금. 그 전에는 1번 자리가 빈 채로 있다.
- 느림 버튼 기호는 ">"가 아닌 ")" 하나. 색은 기본 속도 버튼과 동일.
- 800 무브 업적은 트로피만 주고 속도 보상은 없다 (원작 답습).
- 공유(Share)는 게임 페이지 링크 복사이며, 한 번 하면 두 게임 모두에서 해금 효과.
- 총이동 업적은 한 판 기준, 누적 아님.
- 업적과 커트라인은 게임별 별도. 커트라인은 추후 조정 예정이므로 코드가 아닌 설정 블록에 두어 "밸런싱은 데이터 수정"이 되게 한다.
- 업적창 요약은 "Mouse Maze 1 · Best 53 turns · Same tile 4 times" 형식.
- 리더보드 등수는 동점자도 전원 다른 번호. 정렬은 점수 내림차순, 제출시각 오름차순 (늦게 낸 사람이 아래).
- 100만등 초과는 "1,000,000+" 표기.
- 동일 미로 중복 제출은 잡지 않는다 ("누가 공유했을 테니 어쩔 수 없다"). 동일 닉네임 + 동일 점수만 중복 처리하고 첫 기록을 유지.
- 제출 제한은 10초에 한 번 정도.
- 시뮬레이션 step cap은 99,999,999. 초과 시 그 값으로 등록하고 운영자가 수동 확인.
- 미로 유효성 검사는 BFS면 충분 (그 이상의 엔지니어링 제안 불필요).

### 협업 수칙 (UI 밖이지만 반복 지적)

- 질문은 팝업 위젯이 아니라 채팅으로.
- 기록급(세계기록) 자료를 요구하지 않는다. 명시적 금지 후 한 번 더 물었다가 강하게 질책받음. 테스트는 작은 픽스처와 무작위 대조로 해결.
- 자료를 기다리는 대신 스스로 만들 수 있는 픽스처는 만든다. "네가 임의로 벽을 배치해보고 시뮬레이터로 돌려서 확인해도 되지 않음?"
- 사용자의 관찰 보고를 오조작으로 해석하지 않는다. 버그 보고에 조작 실수 가능성을 먼저 꺼냈다가 "인성이 쓰레기" 반응. 보고는 사실로 두고 코드에서 원인을 찾고, 못 찾으면 "재현 실패"까지만 말한다.
- 롤백 지시는 토 달지 않고 즉시 수행. 함께 들어온 별개 수정의 유지 여부는 항목별로 분리해 처리.
